# DataSentinel AI

### Evidence-Driven Multi-Agent Data Reliability & Self-Healing Platform

DataSentinel AI is a production-inspired AI/data-engineering project that detects pipeline failures, builds an evidence trail, performs multi-agent root-cause analysis, assigns deterministic confidence and remediation-risk scores, gates automated fixes, validates recovery, and stores incidents for replay and evaluation.

The project intentionally separates **LLM reasoning** from **safety-critical decisions**. Models may propose diagnoses and remediation steps, but confidence, approval requirements, and execution eligibility are computed by explicit rules.

## Why this project is different

- **Evidence-first RCA** — diagnoses must cite structured evidence rather than free-form log guesses.
- **Model arbitration** — Gemini and a local LLaMA/Ollama model can independently diagnose the same incident.
- **Deterministic confidence** — confidence comes from evidence coverage, temporal consistency, lineage consistency, and model agreement.
- **Risk-aware remediation** — low-risk actions can be auto-approved; medium/high-risk changes require human approval or escalation.
- **Validation + rollback** — remediation is not considered complete until data-quality checks pass.
- **Replayable incidents** — historical incidents can be rerun after agent changes for regression testing.

## Quick start

### 1. Create a virtual environment

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. Configure environment

```bash
cp .env.example .env
```

The default `MODEL_MODE=mock` requires no API keys.

### 3. Run the API

```bash
uvicorn app.main:app --reload
```

Open:

- API: `http://localhost:8000`
- Swagger: `http://localhost:8000/docs`

### 4. Create a demo incident

```bash
curl -X POST http://localhost:8000/incidents/demo
```

### 5. Investigate it

```bash
curl -X POST http://localhost:8000/incidents/INCIDENT_ID/investigate
```

### 6. Replay it

```bash
curl -X POST http://localhost:8000/incidents/INCIDENT_ID/replay
```

## Confidence scoring

Confidence is intentionally not generated by the LLM.

```text
confidence =
    35% evidence coverage
  + 25% temporal consistency
  + 20% lineage consistency
  + 20% model agreement
```

Each component is bounded to `[0, 1]`. This makes the score explainable and testable.

## Risk scoring

Risk is also deterministic. The engine considers:

- write scope
- number of downstream assets
- sensitive/financial data flags
- data-loss potential
- SQL/PySpark transformation changes
- rollback availability
- confidence in the diagnosis

Policy:

| Risk | Default action |
|---|---|
| LOW | eligible for auto-remediation |
| MEDIUM | propose fix + human approval |
| HIGH | block auto-remediation and escalate |
